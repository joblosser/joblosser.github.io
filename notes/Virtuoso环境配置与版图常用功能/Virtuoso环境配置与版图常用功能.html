Virtuoso 环境配置与版图常用功能介绍 ​

一、从零搭建一套开发环境的整体流程 ​

从零搭建一套射频 / 集成电路开发环境，可以按下面这个流程来：

从零搭建流程：服务器 → EDA 安装 → License 服务 → 普通用户基础环境 → EDA 变量 → 设计平台 → 三方集成 → 导入数据。

第一步，准备一台服务器或者工作站，只要是一套 Linux 环境就行。

第二步，做 EDA 工具的安装。一般是把安装包放到对应路径然后解压，有些复杂的工具可能需要运行安装包里的 Install 工具，可能是统一界面的，也可能是命令行的；大部分都是只需要直接解压就行。

第三步，把 EDA 工具的 License 服务启动起来。

前三步建议用管理员账号操作，避免普通用户改动安装包或者 License 服务。

第四步，普通用户配置自己的非 EDA 基础环境。

第五步，配置 EDA 环境变量。

第六步，配置设计平台，这里的设计平台主要指 Virtuoso。

第七步，做第三方工具的集成。

第八步，导入项目数据，把集成上去的各类工具做设计流的串联。

前两步完成、EDA 变量配好之后，工具就能脱离设计平台，以自带的 GUI 或者命令行独立启动；在这个基础之上，再做设计平台的配置和第三方集成。

二、License 服务：文件格式、启动与查询 ​

绝大部分 EDA 的 License 服务，都是由 flexNet License Manager 这套软件来管理的。

平时会接触到的命令，比如 lmgrd、lmstat，一般就放在每一家 EDA 工具的安装包底下——比如Cadence、Synopsys、Empyrean 这些厂商都有一套名字相近的 License 工具，可能做了少量定制，但一般可以通用去启动这些 License 服务，因为它本质上只是一个服务。

License 里最关键的，是这一份 License 文件。这份文件给到客户、或者自己要启动的时候，都需要做一定修改，因为它有一定的固定格式。

以下面的 License 文件为例，实际内容大致是这样（可按需修改 hostname / mac_address/ port_number与各 feature）：

text
SERVER  hostname  mac_address  port_number
VENDOR  cdslmd  /path/to/cdslmd  options=xxx
FEATURE xxx  cdslmd  2026.01  01-jan-2027  100
1
2
3

第一行的第一项是固定词 SERVER，第二项是 hostname，可以填 anyhost，也可以填当前要启动 License 进程这台服务器的名字，比如 yourservername。第三项是 MAC 地址。第四项是 port_number，这个 port_number 是为了在同一台机器上如果启动了多种 License 服务，可以通过 port_number 来区分。

第二行的第一项也是一个固定关键词，第二项和第三项是守护进程的名称和路径，因为最后启动了一个服务之后，这个进程会一直在这台服务器上运行，每时每刻都不会断掉。这一行的路径一般在安装包底下也会有。第二行的末尾还可以加一个标签叫 options，options 是一个独立的文件，里面按一定格式可以做 License 权限的管理，比如限制这些 License 生效的服务器、限制特定用户名的用户最多能拿到多少 License、或者为其保留多少 License。所以这是一个 License 配置文件，但不是必须的。

第三行是FEATURE 行。这里的 feature 可能有很多，比如 xxx，yyy，如果有独立 License 的话都算一个 feature。这里面比较重要的信息是版本，以及license的生效时间和到期时间。再一个就是 License 的个数——这里是个数，不是使用人数，因为有可能有些 License 一个人可以使用多个，就是一次任务、一次进程可能启动消耗多个 License。

启动的时候，最好找一台比较稳定的服务器，这台服务器可以和其他所有工作的服务器正常通讯、可以 ping 通，并且尽可能不要重启它，不然所有使用这个服务的 License 工具都会停掉。用 lmgrd -c <license_file> -log log 这个命令来实时观测记录 License 服务有没有正常启动，以及 log 里也会显示每一种 License feature 被哪些用户、什么时候 check out 了多少。

License查询用 lmstat。 lmstat -c <license_file> -a 会列出 License 文件里所有的 feature，以及所有的 License 服务器上所有 feature 的信息和使用情况。

lmstat -c <license_file> -i 只是显示所有的 License 服务器上所有 feature 的总个数与到期时间，但它不显示每个 feature 被哪些用户、check out 了多少。

lmstat -c <license_file> -f <feature> 后面跟上 feature 的名字，就只特定看这一个 feature 的使用情况。 另外，license_file这个位置也可以写它的路径，这里如果写成一个环境变量XXX_LIC_FILE，和它是等效的；变量名各家EDA工具的各不相同，变量值为 portnumber@servers 的形式，可以通过冒号 : 不断拼接成很长的一串，这里面每一台服务器都可以被查询到。

三、用户环境配置 ​

这里的"用户环境"指的是非 EDA 工具，也就是不使用任何 EDA 工具，也一定会经历加载的这些东西。

以bash为例，登录服务器的时候，会先加载一个全局的配置文件，再加载一系列系统级的.sh脚本，这些在搭建服务器这一步就默认配置好了。一层一层加载到第三层，才是用户可以改的 .bash_profile文件，它会判断 home 目录下是否有 .bashrc，再去加载它，这个文件建议用户自行修改，每开一个新的终端都会生效。

最后还可以在终端里直接设置环境变量，它具有最高优先级，直接把前面加载的同名变量覆盖掉。如果不想要这次覆盖，就单独新启一个终端，这样只加载前三步，就不会有第四步引入的变量。

.bashrc 里可以放一些常见的设置。默认一般用 \u、\h 显示当前用户名和当前的 host，\T是显示当前时间、 \W 是显示当前工作目录。

还可以加载一些别名、自定义的功能。比较常用的是 cds，它可以直接进入到一个目录，属于比较简单的一个别名。

还有一个复杂一点的 which2： which 可以查询后面的命令路径，which2 在 which 基础上会直接进入到那个命令的路径底下，也就是 cd 过去，可以快速到达任意一个已知名称的工具的位置。

complete -o bashdefault -o default -o nospace cd
complete -o bashdefault -o default -o nospace ls
complete -o bashdefault -o default -o nospace cp

其他还有一些用户环境的设置，不在这个 .bashrc 里。

终端相关的显示、快捷键、主题颜色，在 preference 界面里设置，可以做自定义的修改。

定时任务用 crontab -e，输入这个命令之后会打开一个文本编辑器，按"分 时 日 月 周"的特定格式写一条命令就会定时执行。

四、EDA 工具的三类环境变量 ​

有的 EDA 工具一层套一层，要改好几个文件，看起来比较复杂。实际上 EDA 工具最主要的是以下三类变量，按这个顺序去捋，结构就会比较明确。

类别典型变量说明
1 · License 类变量（最重要）CDS_LICENSE_FILE、LM_LICENSE_FILE用于访问license服务器，保持通讯，格式 端口号@服务器名。
2 · PATH类变量PATH用于指定命令搜索路径，快速启动应用程序，把工具的安装路径加入 PATH，按PATH添加的先后顺序从前往后依次搜索我们写的命令是在哪一段里，然后去对应执行那个目录下的命令。
3 · 工具相关变量XXX_HOME工具内部程序所需变量，默认配置 / 功能的开启与关闭。

首先最重要的当然是 License 类的变量，比如 CDS_LICENSE_FILE、LM_LICENSE_FILE。它们的格式都是 端口号@服务器名 的形式，可以通过在后面不断添加: 把它补得更长，每一台服务器顺序地去访问。只有定义了这个变量之后，启动对应 EDA 厂商的工具时，它才会自动找到对应的服务器去访问 License。所以 License 类的变量肯定是 EDA 环境设置里最重要的一环。

第二类是 PATH 类的变量。主要是为了能快速使用这些命令，程序内部也能快速访问到对应的命令。比如启动Virtuoso，都是直接敲 virtuoso，不会去敲一长串安装路径底下的绝对路径，那是因为在 EDA 环境配置的时候，已经把这些前面的绝对路径都加到了 PATH 里面。

最后一类是工具相关的一些变量，可能是一些默认配置，或者一些功能的开启与关闭。

五、Virtuoso 平台配置：.cdsinit / .cdsenv 与插件加载 ​

绝大部分开发工作都是基于设计平台去开发的，本文的设计平台主要是 Virtuoso。

Virtuoso 的主要配置文件有两个：.cdsinit 和 .cdsenv，这两个都是点开头的隐藏文件。

它的加载逻辑是：一定会先加载 Virtuoso 安装目录自带的程序里面有的.cdsinit 和 .cdsenv，然后判断当前目录是否存在 .cdsinit、.cdsenv，再去找 home 目录下是否存在。

这两个稍微有点区别：.cdsinit 如果在当前目录下找到了，就不会再去找 home 下的，也就是这两个目录下的.cdsinit 只有一个会被加载，优先加载当前启动目录下的；.cdsenv 是会顺序全部加载，后加载的覆盖之前加载的。

.cdsinit 是 SKILL 脚本的语法格式，主要可以用来加载快捷键、display 的一些设置，只要是能用脚本写出来的操作，全部都可以写到 .cdsinit 里面；更重要的是它会加载插件，第三方工具集成也必须靠 .cdsinit 加载进去。

.cdsenv 主要是 Virtuoso 相关操作上的一些配置，比如各界面导入导出的默认值，是可以在 .cdsenv 里自定义的，每次启动就以 .cdsenv 为主。

.cdsinit 里加载最多的，就是 ddsOpenLibManager，它会自动打开 Library Manager；因为我们正常启动的话，只有一个空空的 CIW，还得手动点一下才会弹出来，这里可以直接在 .cdsinit 里写死。

简单来说，只要找到 EDA 安装目录底下的对应插件的 .il 或者 .ile 文件，直接一个 load，就能正常集成，比较方便。

还有一种特殊的加载集成方式，用到了一个文件叫 libInit.il，它是依存于一个 library 的。

举个例子，一个工艺库底下，它会有一个 libInit.il。启动 Virtuoso 的时候，CIW 里的菜单很少，只有四个；但只要点到的任意一个 cell或者任意一个 library，只要是 attached 到这个 techlibrary 的库上去的时候，都不用打开版图，它自动都会加载——第一次点进去，CIW 里会 load 了很长一串，这是因为 libInit.il 被触发了。它实际上是一条一条 load 了一些东西，然后 CIW 的界面里会多出两个下拉菜单，这也是一种集成的方式。

这个 libInit.il 文件，主要是用于 PDK 库以及 Pcell 库，为了保证自己的 PDK、Pcell 的 SKILL 代码能在每一次运行的时候都被正常解释，所以它会放一个文件放到库里面去，和库进行一个强制关联。

六、版图基础：GDS 结构与三件套文件 ​

版图的定义可能不是那么准确，但可以从几个特点看出，它是为制造做准备、实现电路功能的平面几何图形。

首先它肯定和制造相关，因为 GDS 是为 Mask 做准备的；实现电路功能，就是说电路图和版图肯定要有一个功能一致的对应，这里一般用 Mentor 的 Calibre 工具去跑 LVS（版图与电路图一致性检查）。

最后，版图的本质，实际上是平面几何图形，不管多么复杂的版图，大到 full chip，小到几根金属线，本质上都是由很多个图形组成的。

用 KLayout 等版图编辑器打开一个 layout，看到的是一些图形；给工具去使用的，一般都是 GDS。GDS 实际上只是换了一种工具能识别的模式，去描述这些图形，一般是一个二进制的，但我们可以把它转成一个人可读的文本格式，更好地理解里面到底记录了哪些信息。

工艺里常用的三个文件，一般称为三件套：一个是 Techfile，一个是 LayerMap，一个是 Display。

Techfile 是最重要的，它主要定义了工艺库底下所有的层、以及通孔、层间的连接性、各个层之间的一些物理规定、约束条件等信息，是一个非常常用、也比较复杂的文件，是工艺库必备的一个文件。

LayerMap 文件实际上是一个映射关系，它把 GDS Number、datatype映射到层名上面去。从一个工艺切换到另外一个工艺，如果什么都不变的情况下只变了层名，那把 GDS 里面的层替换到另外一个工艺用的 GDS Number，以后显示出来的就是新工艺里面对应的层。

最后是 Display 文件，它主要是在影响版图编辑器里面的图层样式。 Display 文件只是一个显示上的文件，只影响在版图编辑器里看到的样子，对导出、对验证这些实际上是没什么影响的，所以它是三者之中影响最小的。

最重要的 Techfile 丢失了以后，打开另一个版图，发现这个库底下的所有层都没有了，因为它的层定义、孔定义都丢了，一个可用的层都没有。

GDS 中只记录了 GDS Number 是一个层的数字编码，没有说层名是什么，如果没有 LayerMap 去把它关联到任意一个层，导入的时候就会有问题，因为没有一个层与它对应，它不知道该用哪一个层去显示它、去描述它，就会导入失败。

Display 丢失会把所有的层全部都显示成一种样子，根本就没办法正常去看。所以 Display 它只是影响人去看的这个效果，但这个图是可以进行仿真验证的，可以导出，可以做 DRC、LVS，这些都是正常的，只不过看上去会特别难受。
